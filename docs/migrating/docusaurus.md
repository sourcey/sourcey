# Migrating from Docusaurus

`sourcey migrate docusaurus` reads `docusaurus.config.*`, your sidebars and your docs, and writes a standalone Sourcey project beside them. Your Markdown stays where it is; only the syntax that needs a native form changes.

```bash
npm install            # the configuration is loaded with your own dependencies
npx sourcey migrate docusaurus --dry-run
```

Docusaurus configuration and sidebar files are programs: they can read files, branch on environment variables and call `require.resolve`. The migration loads them the way Docusaurus does, with your installed dependencies and `NODE_ENV=production`, so run it in the environment your production build uses (for example with the same `DOCS_LOCALES` or `.env`). Documents themselves are read, never run.

## Configuration

| Docusaurus | Native Sourcey |
| --- | --- |
| `title`, `url`, `baseUrl`, `trailingSlash` | `name`, `siteUrl`, `baseUrl`, `prettyUrls` |
| docs plugin instances (`routeBasePath`, `path`) | a navigation tab each, at the same route |
| `versions.json`, `versioned_docs`, `versioned_sidebars`, `lastVersion`, `versions` | tab versions with the same paths and labels; `banner` becomes the version's status and `noIndex` keeps it out of search engines |
| `i18n.locales`, `localeConfigs` | `i18n` with the same URL prefixes, labels, language and direction |
| `editUrl` (a string) | `repo`, `editBranch`, `editBasePath` |
| frontmatter `custom_edit_url` | frontmatter `editUrl` (`null` becomes `false`) |
| `staticDirectories` | `publicDir`; several directories are merged into one |
| `themeConfig.navbar` logo, links, doc links and dropdowns, `footer` links and copyright | `logo`, `navbar.links` (dropdowns as menus), `footer.links`, `footer.text` |
| `colorMode`, `--ifm-color-primary` in custom CSS | `theme.appearance`, `theme.colors` |
| `@docusaurus/plugin-client-redirects` (`redirects` and `createRedirects`) | `redirects` |

## Docs and sidebars

Every page keeps its URL, computed as Docusaurus computes it: number prefixes such as `01-intro.md` are dropped, a frontmatter `id` names the page inside its directory, a `slug` is resolved against it, and `index`, `README` or a file named after its directory is the directory's page. The configuration keeps file names as routes (`markdown({ slugs: "file" })`) when that matches most pages; the others get an explicit `slug`.

Sidebars become native navigation in the order Docusaurus showed them, including autogenerated sidebars with `_category_.json` labels, positions and links. A category that links a page lands on it; a generated-index category becomes an authored page listing its section with `<PageCards>`. Pages no sidebar lists stay published, out of the menu. Several sidebars become sections of one navigation.

Each translation moves once from `i18n/<locale>/docusaurus-plugin-content-docs/<version>/` to a directory of the locale's name inside the content it translates, which is where native reads a locale. Untranslated pages fall back to the default language, as they did. Translated category labels become the locale's navigation messages.

## Markdown and components

Pages are read the way your Docusaurus version read them. Docusaurus 3 reads Markdown as MDX 3. Docusaurus 2 read it as MDX 1, where indented lines are code, braces in text are text, and a `<` that opens no HTML tag, such as `<PROXY_IP>`, is a character; the migration keeps those as they were. Components your swizzled `src/theme/MDXComponents` makes available on every page are recognised as if each page imported them.

| Docusaurus | Native Sourcey |
| --- | --- |
| `:::note Title` and `:::note[Title]` admonitions | `:::note[Title]`; `important`, `success` and `secondary` become the callout they rendered as, with their title |
| `` ```mdx-code-block `` | its contents, converted like the rest of the page |
| HTML comments in MDX | kept as written |
| `@theme/Tabs`, `@theme/TabItem` | `Tabs` and `Tab`; native tabs open on their first tab and are chosen per set, so `groupId`, `queryString` and a default tab are listed in the report |
| `@theme/Admonition` | the matching callout |
| `@theme/DocCardList` | `PageCards` for the category the page lands |
| `@docusaurus/Link` | a Markdown link |
| imported Markdown partials | `<Include>` |
| `src/pages/*.md` | [site pages](../configuration.md#site-pages) (`pages: "./src/pages"`), drawn with the site's header and footer as Docusaurus drew them |

## What stops a migration

React pages, your own components (until you convert them in the `--mapping` file), API reference plugins, tag pages and content MDX 3 cannot read stop the migration with the file and line. A React page you are retiring can be listed under `docusaurus.removePages` in the mapping file.
